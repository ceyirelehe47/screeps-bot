## 实施原则

1. 每个共享接口具有单一责任。共享出生策略分发已注册 owner 的准入结果，不读取具体任务 Memory；任务模块负责投入证明与终态。强化辅助只报告准备状态，退役由 owner 决定。
2. 统一读模型保留同 tick 写后读语义。不能仅把全扫搬到另一个文件；TickContext 负责快照，赋值接口同步增量索引，配置服务用 revision 失效。库存影子对账通过 TickContext 显式的独立审计入口读回实时 Game；禁止普通业务使用此入口，以免对账验证自身。
3. 任务写入由 owner API 完成并失效相关 revision；GC 调用同一 owner 清理逻辑，保护活体、正在出生和在途实体。生命周期转换集中校验。
4. 防御每 tick 优先执行且永不熔断。可捕获错误逐房隔离；快照失败对该房采取保守防御，其他房正常。低优先阶段可按预算降载及有界熔断。独立面包屑在 heap 保留或帧已保存时恢复阶段；硬终止丢弃整帧且 VM 重建时只记录完成 tick 缺口，不伪造中断阶段。
5. 路径完整性、预算和业务矩阵分别表达。统一结果必须包含完整/预算不足/静态断路/策略拒绝原因。静态断路退避不得被业务重试清除；同 tick 重入不增加 stuck。
6. 稳定的矩阵策略与布局 revision 进入缓存键；动态占位不污染长期静态失败。小队复用移动执行协议，交通处理分为规划与执行，保持 mounts 前注册 creepApi 与角色 `.work()`。
7. 冷数据使用有界 segment 调度并容忍未激活；事件队列去重、有界且重置后可恢复。市场预检按输入 revision 执行，保留实时交易安全检查。

## 验证与发布

每个原编号任务记录实现、调用方和反例，不能只新增未被生产使用的抽象。服务器运行类型检查、无过滤 `test:verify`、构建和映射验收；有界线上观察验证身份、故障、CPU 与业务状态。发布后的证据保存于忽略目录，不为勾选文档而使 main 超前线上。阶段性发布后仍保留未完成任务和活跃目标，直到全清单验收。

## 已核实的平台边界

官方开源 [driver/runtime.js](https://github.com/screeps/driver/blob/master/lib/runtime/runtime.js) 在用户脚本返回后才序列化 Memory；[driver/make.js](https://github.com/screeps/driver/blob/master/lib/runtime/make.js) 的强制超时路径可能直接清除 VM。因此未保存帧与 VM 同时丢失时，不能恢复精确阶段。测试分别覆盖已保存未完成帧、保留 heap 和丢弃帧后的缺口，不能以普通 JavaScript throw 代替硬终止证明。

持续故障通知按错误类型限频：同一 scope 连续 10 次执行失败才升级通知（同 tick 仅计一次，间隔运行也保留连续失败计数），同 scope 至少间隔 1000 tick，全局至少间隔 100 tick；关键防御继续重试。
