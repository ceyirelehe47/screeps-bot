## 背景

以 0b6ef5f3（运行源码为 6878c3f）为冻结基线。线上共享寻路已能让三处 Bank 主队攻击，但 E3N60 增援在北边 31/32 列的墙前停止超过 500 tick；主队当时剩约 360 tick，剩余击破仅需约 153 tick。当前增援寿命门错误地相加击破时间和接班提前量。

清剿保存了 16/18 跳人工路线。tick 74108518 的原生 `Game.map.findRoute` 确认 E1N57 到 E3N53、E2N54 均存在 6 跳路线，经过 E1N56、E2N56、E2N55、E3N55、E3N54。此前 8/16 跳结果带有 PowerBank 避险名单，不能称为地图最短距离。独立房间对象 API 确认 E3N54 当前无主；清剿不能直接继承资源采集的永久危险名单。

tick 74108620–74108650，W2N60 任务的两人停在 W2N57 北侧 (39,1)/(40,1)，满血无疲劳，出口地形可行。独立房间对象 API 确认下一房 W2N58 是敌方 RCL8、六座塔。所有权执行门正确拒绝，但规划仅避开当前可见有主房，失去视野后反复选择旧路；因此必须保存已确认所有权，直到新视野证明无主或己方。

用户明确本轮要求：低级 NPC 优先无强化、能力不足再用 T3；下一落点的炮塔伤害低于有效治疗量即可推进；PowerBank 必须绕开其他玩家有主房间。

## 目标与边界

目标是改善同 tick 查询架构、减少 CPU 和无效生产资源投入，并使共用行军器的双人出口、所有权和清剿推进语义可验证。

本轮保留主循环顺序、任务和世代所有权、Memory 分区及交易授权。用户后续明确授权“修复问题后也可以直接上线，无需我批准”，因此修复完成验证后直接发布并核验运行状态。服务器回归和 Node 性能证据不自动构成正式 shard1 的性能验收。

## 实现决定

1. 静态证据、tick 级查询和即时执行门分层。Observer 活跃集合、可达查询和双人格占用采用 tick 级共享结果；房间状态、塔能、身体损毁、体力与意图各按其有效边界重新核对。禁止长期缓存敌我或血量判断。
2. PowerBank 增援先证明主队不足。主队 TTL 大于剩余击破时间加原安全余量时立即返回，避免进入昂贵的接班计划。确需接班时根据孵化、强化、行军提前量安排；失去能力和无攻击进展仍可强制恢复。
3. 双人出口先检查来源尝试格与目标落地格，再检查相邻关系。若当前并排出口被墙挡住，在房内 1/48 排位线同步横移到最近合法双格，保留实际意图回执与第二次提交失败时的撤销语义。候选先做数值范围校验，再创建 RoomPosition。
4. PowerBank 规划加入原生视野确认的敌方有主房间，失去视野保留情报，新视野证明无主/己方才删除。实际跨房必须有目标房视野并重新验证控制器所有权。未知房通过 Observer 请求取得视野；己方房间可用于返仓，已处于错误房的队伍可退出。
5. 清剿逐步计算双方可能承受的合并塔伤和有效 HEAL。严格小于治疗量的格允许推进，塔伤增加、HEAL 损毁、搭档分离或退路余量不足时停止或撤退。不能仅以塔完全空或总血量比例决定推进。
6. 清剿路线在任务层生成并记录代价、避让原因和版本；显式人工路线保留授权语义。历史任务的路线迁移必须保持搭档和世代，不通过 stopWar 或直接覆写 roleArgs 修复。

## 风险与取舍

- 双格出口不可行时保持等待并给出阻塞原因，不以拆队盲跨解除等待。
- Observer 请求会影响视野槽位；保持四类队列总量、TTL、轮转公平和单意图发布点。
- 治疗尚未结算，下一步需要承受本轮伤害；以实际可治疗部件和退路保留余量，不能预支满血。
- Node 用时受宿主和 JIT 影响；同时报告原生查询次数、构造次数和相同输入的输出等价性，不宣称这些就是线上 CPU 节省。
