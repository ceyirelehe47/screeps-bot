## Context

用户要求先优化 PowerBank 小队：Observer 自动发现，按实际寻路距离决定是否开采，不再硬编码巡逻房间。只读正式快照见仓库外证据目录，当前八个 RCL8 房间各有 Observer，存在两个任务与六个成员，因此新字段必须兼容旧活动任务。

## Goals / Non-Goals

目标是动态覆盖、完整路径评估、可恢复观察等待、战斗威胁拒绝，以及可靠往返。暂不扩展主动 PvP、生产发布或市场策略。

## Decisions

1. 候选高速房由来源房位置生成，使用标准世界坐标处理 E/W、N/S 的零轴，并排除闭房和世界边界。Observer 覆盖判定使用独立来源集合，不能以自身可达集合自证覆盖；Scout 补盲也使用动态集合。
2. 复看请求只排队，不从 Harvest 直接调用 observeRoom。每个 Observer 每 tick 最多发布一次观察，多个 Observer 不重复同房，失败继续轮转；请求最多64项、25 tick清理。
3. 完整 PathFinder 路径必须在安全 routeRooms 内、连续相邻且实际到达同房目标 range1。源点是实际 active Spawn；名义返程终点按来源 Terminal/Storage 接收偏好选择。未知中转房仅具地形证据，实际交通与未来地形/结构变化由既有缓冲和运行期重新寻路承接，不称已证明全世界静态安全。
4. 测量最多每 tick 一组、每组三次搜索、每次6000 ops；heap缓存最多64项、100 tick有效，关键端点、路线、危险集合、身体与可见拓扑变化失效。未测预算等待不占缓存、不冒充不可达；所有可评估来源及其 active Spawn 测完才选择。
5. 任务新增可选 tile距离、战斗旅行、空载去程、满载名义返程四个数值。旧任务缺字段按原房间数估算；名义来源返程不作为任意备用目的地的 TTL 证明。缺视野/目标确认/威胁/测路等待保留 discovered，绝对 Bank 过期仍优先执行。
6. Hauler 回程必须截取或反向当前到来源的路线；旧参数路线也需定向，走廊外动态恢复。卸货返回矿场后通过真实 mount 的阶段协议切回拾取。
7. 原生上线试运行显示，仅限制 PF 次数没有限制预算外的观察/拓扑/来源前置工作。预算耗尽时必须在新候选的昂贵读取之前等待；缓存命中仍验证当前状态与几何。Harvest 可以分 tick 完成测量，但最终准入仍需当次完整来源评估，不能选部分结果。单测量复用状态、地形、道路与疲劳读取；动态搜房集合只在同 tick、同 Game、同输入内复用，返回副本，跨 tick 重读状态。

## Risks / Trade-offs

- 搜索范围扩大增加成本：观察轮巡与测路次数均有界，缓存只保存数学几何结果。
- 源点/地形时间属于计划：不替代实际交通、敌情、掉落期限与目的地容量校验。
- 旧活动任务不具新距离：维持 fallback，不因当前 Observer 覆盖集合改变而中止任务。

## Migration Plan

先保留旧源码反例红灯，再验证同样反例转绿；完成相关领域、类型、主循环与架构门、构建、独立审查后提交候选。本轮保持未上传，正式执行需要独立部署范围。
