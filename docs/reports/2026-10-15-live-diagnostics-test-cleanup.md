# 2026-10-15 实况诊断与测试清理

本次处理三个具体问题：E3N53 小队停在入口袋内、有可达通路仍计划拆墙，以及自动 Invader 回收错误进入玩家房。此前用例通过没有覆盖这些现场条件，不能据此声称寻路或任务行为正确。

## 现场依据与修复范围

- E3N53 的连续 20 tick 记录中，红绿位于 `(40,1)`、`(41,1)`，满血、无疲劳且没有位移。该入口袋与核心之间被墙封住，但北侧另有开放入口。修复优先退回 E3N54，在源房重排后使用开放入口；真正无开放通路时仍允许规划必要突破。
- 原突破规划复用了退出安全约束后的矩阵，墙后可达区域已被写成不可达；只放开墙格无法证明后续路径。现在开放寻路保留执行约束，突破规划另读物理几何；实际第一步仍经过当前安全门。
- 入口候选共享两房连通图，不逐候选调用寻路。仅原生地形事实在同一 Game、tick、map 与读取函数身份下复用；墙、工地、守军、塔伤、身体及最终跨房许可每次重读。
- 另查明生产移动 receipt 与多个测试适配器共用了错误的逐轴截断假设。官方引擎先丢弃整条越界移动，再从原位置独立处理边缘迁房；PowerCreep 也委托同一移动处理。落点预测与适配器须遵守完整处理链，不能只看底层 `movement.add`。依据为官方固定提交 [普通移动](https://github.com/screeps/engine/blob/a90d26fc9eb943147799e65d0bf9d4d0d79a2722/src/processor/intents/creeps/move.js#L30-L34)、[边缘迁房](https://github.com/screeps/engine/blob/a90d26fc9eb943147799e65d0bf9d4d0d79a2722/src/processor/intents/creeps/tick.js#L49-L78)、[PowerCreep 委托](https://github.com/screeps/engine/blob/a90d26fc9eb943147799e65d0bf9d4d0d79a2722/src/processor/intents/power-creeps/move.js#L8)。
- E2N55 没有直达 E2N54 的出口，绕东侧本身不能认定为路径错误。console 确认实际目的房 E2N54 属于 TooAngel，说明自动回收资格错误。现在仅当前 NPC Invader 身份或可识别遗产可授权；非法旧任务停止生产、回收空车，已载货车辆保留归仓能力。普通手工 HAUL 保持原用途。

## 测试执行完整性

`npm run test:verify` 只执行一次无过滤的 Jest，保存原始发现列表、结果、输出与执行元数据，并核对 Git 跟踪、磁盘、Jest 发现、实际结果四个文件集合一致。禁止 focus、skip、todo、failing 及别名形式，拒绝空 suite、pending、运行时错误和掉例。

`npm run test:budget -- --results <目录>/results.json` 保留旧命令兼容，重新核对同一批原始证据及当前源码指纹，不重跑测试。它证明测试是否完整执行，不能证明断言有价值；用例质量仍须用具体故障复现和行为审查判断。

构建、类型检查和所有 Jest 均在隔离服务器执行。本机仅编辑、轻量查询、接收产物及控制部署。

## console 优先

更新 `.codex/skills/screeps-game-data/SKILL.md`，默认先用一次 console 查询实际 Game 与 heap，不强制先抓完整 Memory、扫描各 shard 或写 Memory probe。`monitor:inspect` 提供 movement、pair、threats 三种固定模式，按问题只选一种；先订阅，后单次提交，必须捕获同一 requestId 的结果并核对实际 shard、tick、部署版本。

字段、表达式与输出有限额，失败不盲目重试，凭据只在本机内存读取。连续位移使用有界房间订阅，单次快照不能证明持续推进。用法见 [console 诊断说明](../monitor-inspect.md)。

真实试读已取得对应 requestId 的 shard1/v3 结果：tick `74349204` 时 E3N53 没有自有 creep；独立前缀查询在 tick `74349293` 找到新生红绿 `meleeAttacker-74349131`、`healer-74349131`，仍在 E1N57，目标 E3N53，阶段 approach。旧小队轨迹不能冒充当前状态。

后续 tick `74349540` 的一次 movement 查询确认同一新队已到 E3N53，再次停在 `(40,1)`、`(41,1)`，双满血、零疲劳，双方 heap 中 travel/path 为空。这是修复发布前可用于同队对照的新鲜基线。

试读期间还发现协议解析会把时间心跳数字中的 `429` 当作限流；已改为识别明确限流状态或文字，增加包含 `429` 的真实时间戳反例，并经服务器复验和新一次线上查询通过。该潜在误判不作为服务器实际限流证据。
