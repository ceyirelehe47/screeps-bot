# 自验收与独立验收

**所有适用项有可检查结果，失败项自行修复并重跑后，才能提交对应阶段完成。** 下面是语义验收项，不是要求新建固定数据schema或凑固定测试数。

## A. 真实需求与阻塞

核对 canonical 任务、创建身份、用途、源/目标真实所有权与结构；UH2O 需求仍成立且未由别的在途/任务重复覆盖。列出完整的该资源/费用/容量占用，指出旧路径停在哪条实际分支，区分正确拒绝、缺陷与尚未证实原因。历史任务完成/取消、同ID新创建、fresh任务选择均有正确处理；无任务不伪造。此项不通过，禁止正式arm。

## B. 产品正式入口回归

| 必测组 | 验收要求 |
| --- | --- |
| UH正式路径 | 正式入口接到UH对应的资源、路线、真实任务、适配语义和postings，不能仍读H字段或只用实验main。 |
| 新旧身份分离 | 原H持久状态仍可读/恢复，旧配额与新活动均不能重置；仅改run/control ID无法绕过旧未结责任。新UH grant不能授权H、OH、其它房间或另一个任务。 |
| 数量/费用 | 余量1、99、100、101、1715；数量<=100且<=余量；超过费用、安全整数或结构条件被拒；UH与Energy分别记账。 |
| 承诺交接 | 只排除所接管100，不排除剩余1615；旧任务、work、生产预约、carrier在途、接收容量、费用不双计/漏计；同ID新任务不继承。 |
| 旧路径竞态 | normal dispatcher/console先后、task已推进、普通send/deal先行、接管先行；只能按当前任务事实接纳或拒绝，不能手工暂停旧系统制造成功。 |
| 真实两端 | E4N58与E1N57均覆盖第三房入库/出库/market/cargo；旧E3N59的保护与新作用域分开验证，禁止误锁无关房间。 |
| carrier | 已在途、已持货、取货/交付两个顺序；真实role动作在相关fence中延后，解除后正常继续，不丢计划或货物。 |
| 执行/确认 | OK只进待证状态；non-OK、不合约返回、throw、交易缺失/重复/相互矛盾、Store扰动、外来变更均不错误确认。 |
| reset各边界 | 控制持久前后、lease preparing、admission未quota、quota未调用、调用边界、native后待确认、确认待清理；恢复原attempt，不重发/双扣。 |
| 退出 | 60秒失联、600tick、30分钟、任务/端点/部署身份漂移；无责任自动closed/OFF，旧路径获得正向机会；有责任drain保留后续恢复。 |
| 业务状态 | pending/done/cancelled/failed、清理、同ID新任务；原确认恰扣一次且保留取消状态；不得清掉唯一关联。 |
| 损坏与持久失败 | control主/镜像、quota、kernel、lease、任务根、未知版本与关闭写失败；坏表不当空，无安全证据不释放。 |
| 默认OFF | 新旧切片默认OFF且无责任时无native、无隐藏迁移，旧市场/物流入口不被阻断；旧不透明责任存在时不可绕过。 |
| 共享兼容 | 改动涉及的main、task retention、arbiter、capacity/reservation、市场Direct与carrier实际组均执行；不得仅用旧H全绿代替UH覆盖。 |
| 生命周期负担 | 避免每个carrier动作重建全帝国索引/反复全Memory序列化；需要缓存时保证同tick新写责任立刻失效重读。只作有证据的必要修正，不重开2CPU项目。 |

先让新增的错误绑定/资源语义/并发反例在待改实现上暴露失败，再修并保留原失败证据；不要求重演已经验收的老缺陷。开发跑受影响组；冻结前实际相关组合 + `npm run typecheck` + `npm run build`；套件名从仓库识别，不空跑、不过滤掉失败项。旧验证继承与本轮新跑分开列。

## C. 同一最终构建的隔离引擎

复用已许可隔离世界或独立副本，核对账号/端口/数据库/服务。合成任务、故障与重置只限实验，原件只追加。

**C1 UH首片与余量交回。** 创建等价1715 UH隔离任务（明确合成），正常production入口经新适配真实发送100 UH并确认；证明首次结算对应1615，重复恢复不再扣；本次额度消费事实保留。责任解除后旧正常路径可继续余量，区分两套交易来源，不把总1715算作国库发送。再验正好100→0终态，可用独立隔离实例组合完成。

**C2 新端点并发与未知恢复。** 用新E4/E1两端验证普通第三房入库先于T2与T2先于普通动作；真实carrier执行点遵守保护，解除后恢复。真实T2发送后用明确可撤销故障暂时阻断确认，保存实际注入读回；OFF/失联/进程重启仍保留原attempt、quota、task与必要fence，无关任务可工作。只撤除实验故障，不手造receipt，证据恢复后原attempt恰结一次、交回。

**C3 无责任退出与禁止重开。** 新UH活动已绑定但尚未接纳，真实失联超过60秒；不调用operator close、不手写mode，证明自动关闭/OFF后旧合法业务取得真实执行机会。600tick/30分钟其余边界用产品回归覆盖；不为重复时长做额外整轮实验。闭合后真实重启不重发；旧H已消费/未结状态与新T2隔离关系由组合回归证明。

同一最终运行main SHA须覆盖所有新受影响实机事实。carrier装夹如仅“合成已持货”，明确只证明持货保护/交付，不声称自然spawn→pickup链；Store合成故障不能代替真实native。既有旧SHA证据只能标继承。

## D. 冻结、独立审查与正式业务

独立reviewer确认精确代码/产物身份、业务授权绑定、源和目标保护、恰扣一次、旧H兼容、退出恢复及产品/原件一致。任何运行字节、依赖或语义修改后重验受影响部分；不可用旧签署冒充新适配审查。

发布后证据必须显示现场独立代码读回、新运行tag与推进tick，先保持OFF，无意外迁移/arm。市场配置不变之外还应核实相关permit/receipt链、高水位、pending连续性；允许正常市场合法推进，不机械要求前后账本完全相等。

正式唯一首片的验收链：新鲜真实需求/任务 → 持久接管身份与额度 → 唯一真实native → 同attempt唯一交易与两端实货/费用确认 → 业务余量只扣一次 → work闭合/已消费事实保留/租约关闭 → 新端点可交回，旧业务持续。无交易、证据不足、未知未结或不合理业务影响，不写“首次生产接管通过”。

没有任务或合法保护拒绝是业务停点，不是工程故障也不是首笔通过。此时交全部可用候选、根因/未知、证据及唯一后继建议；不得把整包宣布全面完成。
