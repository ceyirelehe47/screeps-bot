# T2-PROD-01 任务书

## 1. 本轮唯一新成果

在既有正式 `main → resourceControl → Treasury facade/kernel → 唯一 terminal gateway` 路径中，让 **E4N58 → E1N57 的 UH 合成补料首片**承担真实执行责任，最多一次 native、100 UH、100 Energy 费用；以实际交易和库存证据确认，再恰扣任务一次并关闭责任、交回余量。

这条 UH 能力是本轮需实现的新适配，现有固定 H 首片不能直接启用它。不要通过全局替换 H/房间常量、重用旧配额、手工 `terminal.send` 或实验 main 冒充生产接管。

## 2. 真实业务诊断先于扩大权限

首选历史任务为 `74073650:1:UH:E4N58->E1N57`，归档创建 tick74073650、总量/余量1715、origin automatic、reason `synthesis:E1N57:UH2O`。原文在包中，但进入现场必须读取 canonical 原任务，核对当前生产者仍有 UH2O 补料需求、任务未取消/被替代，且没有同需求已到货或在途覆盖。

若它已经完成/失效，只能在首次绑定前选择同一路线、UH 资源、同 UH2O 用途的新鲜既有自动任务；记录替换原因和真实创建身份。不存在同范围合法任务时不造、不复活、不手工补货，不自动换路线/资源。

至少查清以下链条，并将已证实根因、暂时阻塞与未知分开：

- 需求：合成配置、当前活跃产品/缺料、任务 origin/reason、其他有效入库或本地供应；不能从“目标 UH=0”或“pending 很久”直接断言需要发送。
- 供货：Terminal 与 Storage 分别有多少 UH/费用 Energy，已保护储备、生产预约、市场承诺和其他合法资源占用；库存不是全可用。
- 搬运：是否存在该任务对应的 staging、carrier 分配/在途/交付、终端回收；现有实货不足时沿正常链路自然备货，不另造专用运输指令。
- 执行：taskMaxPerRun/排序、终端 cooldown、已发生的 send/deal、费用与接收容量承诺；输出候选在各门槛被拒的可追溯理由。归档中的能量双向发送只是线索，不预判为本任务根因。

首选任务仍 pending 且实货足够时，必须解释旧路径没有推进的原因或剩余不确定性。若是正确的保护拒绝，国库同样拒绝；若是遗漏清理/错误占用/同责任双计等工程错误，最小修复并补回归。不要为了证明国库价值任意抢占旧任务、降低储备或切断其他物流。

没有匹配任务不妨碍离线实现和隔离验收；也不应反复现场空等。一次有界只读观察不能超过600个新tick或30分钟，先到即止，不要求耗满；结束时给需求原因与至多一个真实后继建议，不自动执行超范围任务。

## 3. 最小适配与可恢复授权

沿现有执行系统增加 UH 切片能力：授权绑定资源、源/目标房间、真实结构与所有者、task ID/创建身份/总量/接管时余量、用途、代码身份、唯一活动、一次额度与固定截止。具体内部表示由 Agent 设计，不能仅凭 actor 字符串或可随意重放的 console 参数绕过授权。

事务持久事实必须足以在堆重置后识别 UH、两端、费用、原任务和原 attempt；实际 receipt/description 与新语义一致。旧 H 编码和恢复保持可辨认，未知或歧义不猜。

允许最小参数化来复用后续同类终端转运，但本轮公开生效的权限只含这一条 UH lane；不顺便开放任意路线、任意非 Energy 资源或任意接管额度。T1 和 T2 不能并行取得相同资源/终端窗口；旧 T1 或其他相关 Treasury 未结/损坏责任存在时，不启动 T2。

控制实例在可发送前持久绑定一次。接纳后原 attempt 是唯一责任身份，哪怕发生 non-OK、异常、未知、cancel 或接纳后中断，也不得创建第二个 attempt 试错。尚未接纳的冲突可以在同一未到期窗口内重新评估，但不能延长截止或自动换 task。旧活动、已关闭新活动、已消费额度不因 reload、deploy、目录或改名复活。

## 4. 旧业务责任与内核责任只算一次

接管只针对原任务的最多100 UH切片，不把整个1715任务排除出库存/接收责任。原任务其余部分继续保留承诺。尚未确认的切片由国库 work承担，不能旧任务和work双计，也不能两者均不计；费用与目标容量亦如此。

共享 source/target 容量与资源占用统一计算，临接纳和 native 前二次核验。不得沿用旧 H 首片的裸库存判断，绕过本轮 UH 生产预约、现役市场保护和普通接收余量。

为获得接管窗口需要少量受控授权/租约状态，必须由产品入口原子核对任务及占用后写入。这属于适用授权中的产品接管，不是人工制造任务。不能先禁用全局 resourceControl 或暂停旧市场，凑出窗口；console 与 main 的先后竞态由产品检查安全处理。

## 5. 两端隔离必须真正换到 E4N58 / E1N57

不能只改发送的目的地而仍保护旧 E3N59。新切片持有责任时，两个真实端点的普通 send/deal、第三房入库、普通 carrier withdraw/transfer 和已有持货交付均需遵守同一可恢复保护。普通动作先行与 Treasury 先行两个顺序都要覆盖。

两房有既存市场/费用/生产活动，应核对当前 pending、terminal/account claim 与在途，不用“市场配置没变”代替责任检查。复用既有仲裁；未知责任只阻挡必要范围，其他合法房间和任务继续。无法阻挡的外来交易/世界效果需充分归因，不能仅放松 Store 等式判成功。

默认 OFF、没有旧新责任时，无隐藏预约迁移、无新发送、无无谓全局冻结。新切片到期、控制失联、身份漂移的处理沿已修生命周期：无责任自动关闭/OFF；有责任停新增并继续原对账；损坏状态拒绝误交回。

## 6. 发送、确认、余量与交回

native 前持久封住本次额度并记录执行边界；返回 OK 不是确认。按照原服务语义结合唯一交易、真实资源/费用和两端 Store 证明结果。未知不扣余量、不补发；not_executed 不扣；committed 恰扣一次。任务同时被取消/failed时保留业务状态，不丢原动作实际结论。

例如启动时仍有1715 UH，国库确认100后，任务业务余量应先对应1615；若普通路径随后自然发送更多，最终快照可能更小，必须用同身份事件、交易和扣减证据分离两部分，而不是强行要求所有后续快照保持1615。

国库责任结清后，保存已消费事实，释放本切片自己的租约/隔离，并由旧路径接手余量。不能调用旧writer手工补送作为验收。旧路径继续发送的数量不计作Treasury成交；剩余业务因合理阻塞仍pending也不应篡改为done。

对账与交回要有正向证据：原attempt闭合、旧路径重新可执行、普通业务仍推进。没有合适普通动作时用产品状态与隔离正向证据限定结论，不以“没有错误日志”宣称生产旧路径已经完成余量。

## 7. 冻结及生产闭环

最小适配与阻塞修正一并完成，相关产品测试和同一最终字节的 UH 隔离链通过后进行独立审查。只发布一份已验证默认 OFF 候选；确认实际运行后，在同一轮执行一次有界接管并对账。不要先随意热上传一版再靠线上试错修。

工程就绪却无同范围真实需求时，通常不再为首次业务重复做一轮纯 OFF 发布；保留当前安全版本，交候选与明确业务停点。若另有确证安全缺陷必须独立 OFF 更新，清楚说明原因，不将它冒充本轮首笔通过。
