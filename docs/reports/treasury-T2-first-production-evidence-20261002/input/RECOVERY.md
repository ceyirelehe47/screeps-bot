# 停止、责任恢复与回退

停止新增、关闭执行责任、交回旧业务是三个不同动作。新活动的时间和次数上限不得变成“到点清账”的理由。

**未绑定、未接纳。** 保持OFF；只读诊断不会产生发送许可。失效历史任务不复活。

**已绑定但完整证明无quota/work/lease责任。** 到期/失联/漂移应自动持久closed/OFF并交回，不依赖pending扫描；不重复arm取第二次窗口。关闭持久写失败时按已验收语义保守处理，不能假称已恢复。

**已接纳、尚未跨native。** 必须由原内核持久调用边界证明未执行，才可沿同attempt取消/结算并关闭；reserved、超时、缺交易都不是未调用的充分证明。admission未quota的reset恢复原身份，不新建另一笔资格。

**可能已调用/结果未知。** 保留原额度、work、业务关联、两端必要隔离及能读它们的代码；T1/T2新接纳关闭，不补发、清quota、删marker或还原历史Memory。无关房间仍应工作。充分真实证据出现后沿原恢复路径确认一次，若不足则记录仍unknown。

**已确认待清理。** 依据同attempt结论关闭lease/work，保留已消费事实。重复recover/off/reset不再扣减。done/cancelled/failed和被清理候选不应丢唯一身份；同ID新任务不继承旧许可或结果。

**新状态损坏或结构/所有权改变。** 坏根、未知版本、主镜像矛盾、外来Store变更不当作空；停止新接纳，记录范围与恢复所需证据。不能用手造receipt或模糊放宽等式强行成功。

**代码发布异常。** POST不明先独立GET，未证实失败不重发；如果已发生新语义迁移或work，即便旧 `447ab5c` 曾上线，也不自动证明它可解释UH新责任。优先当前候选内停止新增并保留恢复；需要另一份hotfix/rollback时必须说明精确兼容性与新的发布边界，不在本轮一次发布额度外偷偷执行。任何回退不恢复整份旧Memory。

本包不授权新的第二笔资源动作、不授权删原任务重建、不授权回补资金/资源抵消失败。收尾失败是需要修复的产品问题，不是可以通过重置世界完成的验收手续。
