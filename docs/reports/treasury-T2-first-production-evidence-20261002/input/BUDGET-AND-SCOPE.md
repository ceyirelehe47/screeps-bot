# 本轮预算与作用域

以下是 T2-PROD-01 新提出的固定外部边界，须与用户直接授权一同生效，不是已上线 T1 的现状。

| 项目 | 上限或规则 |
| --- | --- |
| 生产账号/目标 | forster / 634fe406347a7b69b28aeccb；screeps.com；代码default；业务shard1 |
| 业务 | E4N58→E1N57，UH，既有自动 UH2O 合成补料任务 |
| 选任务 | 首选74073650:1:UH:E4N58->E1N57；若失效，首次绑定前可选同范围新鲜既有任务；绑定后禁止切换 |
| Treasury活动 | 一次有界控制活动；不自动重开；一次已接纳责任的原attempt贯穿结束 |
| native/资源 | 最多一次 Treasury terminal.send 调用；数量1–100 UH，且≤绑定余量；失败/异常/未知不补次数 |
| 费用 | native实时报价≤100 Energy；实际核对费用单列；不减少其他储备/占用 |
| 截止 | 绑定/arm起最多600 tick或30分钟，先到停止新增；不得从首次send再重置时钟 |
| 控制租约 | 最长60秒，续租不延长活动固定截止；失联后下一可运行tick停新增 |
| 并发 | 本次至多一个国库未结切片；遵守共享终端和现役市场的更严排他条件 |
| CPU/Memory | 复用并至少保留native前剩余CPU20、bucket2000、Memory真实UTF-8<1,900,000；不是长期性能合格线 |
| 运行产物 | 采用既有发布约束，保持保守main<5,000,000字节；若模块集合改变必须重新审查，不以build成功代替可上传 |
| 代码发布 | 本轮至多一份独立审查通过候选的生产上传；未知POST先读回不重发；需要第二份发布需新明确边界 |
| 只读准备 | 优先立即判定，不为凑时长等待；一次准备观察至多600新tick或30分钟，无未来后台观察活动 |

600 tick/30分钟约束的是**新接纳**，不是强制清除责任的时间。若临到期仍unknown，保留对账代码/原责任，禁止清状态以满足退出时限。游戏没有推进tick时不能声称游戏内部已按墙钟执行了关闭。

本次Treasury预算不包括未被暂停的正常旧物流/市场自身合法工作，后者沿原政策运行。但禁止人为调用旧业务补送来规避本次上限。旧任务余量保留不是给予第二笔Treasury资格。

无新美元、token或Agent算力费用授权。开发中按受影响范围测试、冻结前相关组合；不要用任意测试数量或一次全仓慢跑作为进度目标，也不要为节省成本省略必要安全用例。
