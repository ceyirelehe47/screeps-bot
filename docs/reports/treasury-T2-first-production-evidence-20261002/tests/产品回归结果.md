## 业务停点反例

绑定 fixture 具有有效且未被本地供应覆盖的 UH2O 需求：配置与 runtime 一致的 `targetAmount=5000, batchSize=2500`，试验使用 UH+OH 的真实反应语义。单独反例证明：目标 UH2O=2385、成品=1885、UH reagent lab=500 时，旧 pending 1715 UH task 不得 arm；另一个健康 UH 入库已覆盖有效缺口时也不得重复 arm。没有靠 task.reason 或目标 Terminal UH=0 单独授权。

新增 cargo suite 中 PowerBank 已持货、remoteMining 在合法 arm/send 后的后续 Storage 满视图均明确是合成装夹，只证明该存量角色执行点的保护与交回；不声称自然 PowerBank 活动、自然填满链或现场 PowerCreep 行为。

## 失败证据与修复核验

- `t2-baseline-red.txt`：在 UH 产品能力尚未实现时，独立 contract 与 T2 绑定入口两个断言失败。最终相同断言通过。
- `t2-product-red.txt`：初次实际行为组合中，原 H 接口被 UH policy 单槽覆盖而无法通过正式 admission 的新兼容反例失败；最终真实 H 先完成再 T2 接管的用例通过。该日志同时包含 typed 预约 fixture 尚未正确装夹的失败，不能将所有失败都计作产品缺陷。
- `t2-native-boundary-regression.txt` / `t2-boundary-transient-regression.txt`：新增费用正向边界发现只按 room-total 判断会 arm，而 kernel 的 terminal 所有权门拒绝。最终 readiness 采用两者保守交集；9980/9981 的 Terminal fee 预约边界正负均通过，89980 room-total 有余额但 Terminal scope 不成立的反例在 arm 前拒绝。
- `t2-malformed-native-reconstructed-red.txt` 与 `.patch.diff`：在独立 `/tmp` 副本重建 review 前缺陷，只移除非法 return 校验/throw；6 个 T2/T1 用例全部暴露“已模拟执行却误记 not_executed”。这是**隔离副本重建红证据**，不是原始 pre-fix 跑，也不是实机。最终同样 6 个用例保留 unknown，后按同 attempt 的交易与 Store 恰结一次。
- `t2-dual-reset-reconstructed-red.txt` 与 `.patch.diff`：在独立副本重建双 lane 恢复顺序缺陷，仅去掉 beginTick 前原 attempt 责任发布；组合 reset 反例暴露原身份无法交回。最终先发布原 quota/task closing、再让 kernel sweep 推进，69 例 binding 包含该反例全部通过。该证据同样标为隔离重建。
- `t2-legacy-root-original-red.txt`：修复前实际跑 12 例，5 个失败明确暴露未知版本/未知责任键/null 旧表，以及同 tick 缓存后的原地损坏旁路；最终相同 12 例通过，已识别空 map/list 的兼容用例保留。
- `t2-first-implementation-red.txt` 等施工中编译失败、以及有明确 fixture 原因的早期日志仅为过程记录，不列入最终通过结果。
