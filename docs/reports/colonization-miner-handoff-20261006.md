# 殖民矿工支援交接修复

## 问题与修复

E3N54、E4N57 已达到 RCL3 并建成 Spawn，但分别只有 8、5 个扩展。殖民生命周期进入 `managed` 后提前返回，不再重建母房矿工与建造配置；本地生产又在 RCL3 的 10 个扩展全部完成之前抑制采矿配置。原支援配置丢失后，两房进入无矿工、无持续能量收入的等待状态。

修复只改变 `colonization.ts` 的交接路径：

- 扩展尚未完成时，每 tick 维持每个矿点的母房采矿配置及原有两名建造支援。
- 扩展完成后，本地正常生成采矿配置；母房继续维持尚未有本地矿工出生的矿点。
- 本地 creep 的 `spawning` 状态不再算接班。按矿点撤下旧支援，所有矿点都有已出生本地矿工后才清理殖民任务。
- 保留原来的母房防御暂停、旗帜取消、支援升级策略及路线许可。

没有手动改写生产 Memory 或直接调用 Spawn；支援通过原有生命周期与孵化调度恢复。
