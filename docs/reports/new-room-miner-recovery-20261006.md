## 最终行为

1. 在仍启用的两房支援策略中，为每个矿点持续维护一份母房 `colonizerHarvester` 配置，直至既有 RCL6 停点。配置丢失或解绑可重新绑定，不依赖已删除的殖民旗或任务。当前两房共四份配置，沿用 5 WORK / 5 MOVE、750 能量的既有身体；每份配置沿用最多两个矿工重叠的补员限制。
2. 支援路线保存在运行状态中，绑定来源房与 `runId`。升级者配置丢失后仍能恢复原路线；换运行批次时不继承旧路线。E3N54 沿用 `E1N57 → E1N56 → E2N56 → E2N55 → E3N55 → E3N54`，E4N57 沿用 `E1N57 → E2N57 → E3N57 → E4N57`。E3N57 的既有过境许可仍检查当前战斗威胁。
3. 新房增援矿工使用完整许可路线估算提前补员，包含地形、身体移动能力、孵化、当前 Spawn 占用与队列等待。搜索每 tick 最多一次、最多 2,000 ops，缓存 1,000 tick；部分路径不作为完整通勤，缺少完整路径时按路线跳数保留提前量。原实现只取 `findPathTo` 的数组长度，没有确认跨房结果完整性；新策略明确检查 `PathFinder.search` 的 `incomplete` 标记。[官方 API 说明](https://docs.screeps.com/api/#PathFinder.search)
4. 仅对启用支援策略且不高于 RCL6 的己方新房增加断产恢复：无采矿单位、正常身体付不起时，先孵化可支付的 150 或 250 能量采矿单位；正常身体已可支付时，把缺失矿工排在昂贵 carrier 前。没有 Storage 时额外留出 100 tick 补能和运输时间。
5. 本地矿工已排队但缺能量时，升级支援暂缓取能，释放拾取预留并放下持有的能量。能支付矿工后继续直接升级，不转去建造或维修。
6. RCL6、策略停用、失去房间或母房防御暂停时，清理增援出生资格和队列；现役矿工先解绑，沿原路线返乡回收。解除防御暂停后按原策略恢复。

没有更改常规外矿状态机、战争、国库或主循环顺序；常规房间沿用原孵化策略。新增自动恢复限定到已有新房支援策略。
