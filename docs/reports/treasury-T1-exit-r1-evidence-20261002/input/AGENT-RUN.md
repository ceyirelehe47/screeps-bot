# Agent 执行指令

## 任务边界与工作方式

这是 Treasury T1 的一次完整接续，不是市场任务，也不是新一轮 FC1 诊断。集中完成：增量核对 → 产品补正 → 真实入口/最终字节验证 → 独立审查 → 条件成立时默认 OFF 修复发布及唯一业务灰度 → 对账交回或给出明确业务停点。

内部 schema、类型、文件拆分、最小接线方式由实现者设计。复用现有 lifecycle、control 主/镜像、quota、kernel、任务桥、仲裁器、carrier 和发布/读回工具。不要新建平行权限服务、交易 writer、任务表或全套观察框架；不要直接修改 generated Core。

普通范围内工程问题自主解决，开发时跑受影响测试，冻结前补相关组合。缺少线上任务不妨碍修复和隔离验证。不要为小修复逐条等待用户；不要把“无任务”当作无法推进离线工作的理由。

## 本轮必须的新结果

1. 到期归一化接入每 tick 生命周期，不依赖待处理任务存在；无责任健康状态自动关闭并交回，未知/损坏责任保守恢复。
2. 回归检查“旧业务真正重新获得处理机会”，而不只检查“Treasury 没发送”。最终构建的隔离运行必须覆盖自动退出、未知责任不误释放和原成功发送/收尾链。
3. 提交新鲜的真实需求与准备状态。无匹配任务时说明生产者为什么未产生该需求；有任务无实货时追到既有 staging/carrier 和库存责任。仅在代码与事实支持时定性，不从单次无任务/Terminal=0 推断永久故障。
4. 有直接授权、就绪任务及所有门槛时，连续完成一次受限实写与恢复；否则明确完成到哪一层，并交付真实可用候选/阻塞材料。

## 生产权限

本包本身不授予生产写权限。`AUTHORIZATION.txt` 是用户直接消息的模板。用户已在 Agent 会话提供等价且适用于本轮的直接授权时不反复索要；无授权仍完成离线、隔离和既有许可范围内只读诊断，停在生产写入前。

旧活动因无任务已结束；新直接授权只允许尝试未消费的原 T1 切片额度，不允许换 control/runId 或清 quota 得到第二次机会。任何旧 active/unknown/closed/已消费状态先识别；不能因为换了轮次名就刷新额度。

本轮最多发布一份通过全部门槛的默认 OFF 修复候选；成功发布后不再热换另一份候选试错。结果不明先独立读回，不自动重复 POST。发现必须新增生产代码修补时另冻结并明确新发布边界。

首次 Treasury 发送仍只限 `E3N59 → E4N58` 的既有合法 H 任务，最多一次 native、100 H、100 Energy 真实费用，600 tick/30分钟和60秒控制租约均不放宽。保持市场价格、保护储备、permit/WAL、冷却和 R2 关闭状态；不造任务、手工补货、换路线或启动第二类 writer。

## 发布前独立审查

修复者自查不等于独立审查。可用独立 reviewer 子代理/另一审查者，只读检查精确候选提交、运行产物和本包业务不变量；保留身份、发现、修正及最终结论。若无独立评审条件，完成全部其它工作并交付待审候选，不自签放行生产。不得重复上次“先发布再补称已独立审查”的过程缺口。
