# 交付与审查材料

提交并推送正确仓库的新产品实现、相关回归、可重跑证据验证脚本、脱敏原件、冻结身份和报告。建议新报告 `docs/reports/treasury-T1-exit-r1-20260927.md`，证据放新的同名目录；若已有同名记录追加明确后继，不改写历史读回。

## 报告顺序

先讲业务结果：退出缺口是否修复、默认OFF安全更新是否运行、真实需求/备货是否就绪、T1 native是否发生、是否确认结算并交回、具体停止原因。然后写代码/测试/引擎/生产证据及身份。

把实现通过、mock复现、真实入口回归、最终包隔离验证、正式部署、实际native、确认、责任闭合、普通业务恢复分开。测试数不是验收目标；规划完整不是市场成交；一笔T1不是全系统迁移完成。

## 必交材料

- 精确提交与diff范围、remote核对、工作树/依赖锁身份；相关测试命令/输出/退出码/环境、构建日志。说明哪些结果是继承，不把旧数重报成本轮。
- 自动到期产品回归与引擎原件；无责任自动交回、未知责任保留、成功链和reset的可复核结果。旧源码复现只作历史反例，不冒充修复验证。
- 最终模块清单、字节与文件SHA-256、运行tag与内嵌bundle标识、最终引擎代码读回；不可仅给一个“build成功”。
- 发布前真正独立reviewer的范围、精确候选、结论、发现和已处理说明。未得到独立签署时明确停在候选待审，不自签生产。
- 当前完整任务覆盖的可核对材料、原路线需求来源/是否被覆盖、两房库存和责任、staging/carrier准备与具体阻塞。有合适替代任务时只提出一个有边界的建议，不自动实施。
- 执行了生产写入时：直接授权适用范围的简要记录、不含凭据的每次操作与独立读回、时间/tick、代码/状态/交易/任务/责任/普通业务恢复。未执行时明确哪一门槛未通过。
- 结束状态：control和mode、quota消费事实、active/lease/fence、是否需要继续对账、是否没有留下新的接纳窗口；以及唯一下一动作。

证据校验脚本应从原件推导结论，不只读取另一个verification.json里的passed。新证据原件只读，输出文件另存；完整性校验不等于产品/实机测试。

## 允许的结束分支

**闭环完成：**修复/独立审查/最终构建验证通过，当前直接授权下单笔生产已确认、正确结算、安全交回。

**业务未就绪：**修复及必要验证已完成；按授权可完成一份新的默认OFF安全更新；无就绪原任务时不arm，给出当前有证据的需求/备货结论和后继切片建议或明确缺失前提。这不是首次writer通过。

**相应门槛未通过：**保留已完成工作和可审候选，指出独立审查、权限、环境、责任或产品问题；停止对应生产阶段，不因此省略其余不依赖该门槛的工作。
