# 验收：自动交回必须有正向业务证据

## 1. 产品入口回归

先在修改前用真实模块与正式 `main/lifecycle → resourceControl → Treasury` 接入路径复现，再修改。保留旧抽取反例原件；不要改它的固定源码/断言令其“通过新版本”。新回归另放产品仓库。

| 必测组 | 必须检查什么 |
| --- | --- |
| 60秒失联、600 tick、30分钟固定截止 | 边界前不提前关闭、边界及之后不再准入；健康无责任时control持久关闭、mode有效OFF、旧路径不再因Treasury handled被跳过。不能只断言T1 send=0。 |
| 空队列、task cancelled/done/failed、已清理、同ID新任务 | 不依赖pending扫描；无责任关闭，有责任继续保留精确关联；新任务不继承旧权限/结论。 |
| 接纳前、reserved未调用、native后待确认、确认待清理的reset | 期限、已消费额度、结算身份不丢；重启不重发、不重复扣余量。 |
| 未知或矛盾交易/Store变化，OFF与到期交叉 | 新准入停；unknown、quota、必要fence不被到期清掉；后续充分证据出现时沿原恢复路径结算。 |
| control/quota/kernel/lease损坏、关闭持久写失败 | 坏数据不按空表；无越界native，无额度重置，不能用“写了mode”声称已经恢复。 |
| 关闭后的后续tick/heartbeat/rearm | 不能重开同活动或取得第二次配额；干净默认OFF无隐藏迁移或无谓服务创建。 |
| 旧物流与两端并发 | 无责任退出后旧writer能实际处理合法任务；有责任时两端与carrier保护仍生效；无关房间正常。 |
| 一次性原成功链 | 真实100 H→确认→done/0或正确余量→责任收尾；non-OK/throw/unknown不补次数；已确认金额不会因重复恢复再次扣减。 |
| CPU/Memory/身份/费用/容量门禁 | 保留当前保护；临准入及native前再次核验，期限与安全条件不因新版退出逻辑失效。 |

开发阶段跑受影响组；冻结前组合覆盖 control/lifecycle/T1/task bridge/kernel、resourceControl、预约、arbiter、carrier、市场Direct与main，并完成 `npm run typecheck`、`npm run build`。找实际套件路径，不猜命令、不空跑、不固定必须N项。共享接线/依赖变化扩大相关测试范围；合理精简需保留有效不变量，旧结果继承和新跑要分开。

## 2. 最终构建的真实隔离环境

复用既有合法隔离环境，先核对服务归属、数据库与端口。最终发布字节至少组合完成下面三条，不为每条单独搭建/发布一套环境：

**A. 无责任自动交回（新增重点）。** 建立合法隔离任务并arm，借可说明的调度/准备条件让本次T1尚未接纳；封存无quota/work/lease的证据。让真实生命周期遇到到期，过程中不调用操作员close、不手写mode、不开新授权。证明control关闭、有效OFF，随后普通生产writer通过真实native完成原任务或另一个明确合法任务，且T1 native始终为0。用transaction description/attempt区分普通发送，不把普通发送计入T1额度。暂停/时钟替身/装夹必须明示，不能篡改封存结果；至少失联退出取得真实引擎证明，其余边界由真实产品入口回归覆盖。

**B. 已有未知责任不得误交回（新增重点）。** 在隔离环境封存真实一次T1 native及其责任；用明示的实验装夹暂时使确认信息不可用/矛盾，证明到期/OFF/重启不释放相关fence、不重发、不让旧writer重复同一切片。恢复充分真实证据后应沿产品恢复路径结算；确实不可确定则记录“仍unknown”，不能伪造成功。真实native事实、人为屏蔽/故障注入和产品输出分层保存，不能用手造成功receipt代替引擎交易。

**C. 原成功及并发链不回退。** 同一最终构建仍可正常一次发送100 H、确认、任务结算、责任关闭、旧业务恢复、重启不重发；覆盖普通入库先于T1、T1先于普通入库与carrier延后的受影响组合。既有无关证据可标继承，但不能把旧SHA的引擎结果写成新包实测。

保存源/目标实际Store与结构、任务、control主/镜像、quota/kernel/lease、普通业务动作、交易、carrier持货、时间与tick、代码摘要。保留实验装夹和可重跑验证脚本；原件只追加不覆写。

## 3. 最终审查与生产结论

独立reviewer检查最终源码/产物身份、退出时序、不误放unknown、恢复链与范围。源码/依赖/构建字节变化后重做受影响验证，不能沿用旧签署。原脚本压缩格式和build tag导致的哈希变化需如实处理；发布使用已验证冻结字节，不重新build出另一份再上传。

生产阶段的门槛分别记录：默认OFF修复已运行、原任务就绪、native实际发生、唯一交易确认、业务余量恰扣一次、责任关闭、终端交回。没有任务时只认可相应阶段，不宣布首笔writer通过；一笔闭环不代表全面国库接管或长期稳定。
