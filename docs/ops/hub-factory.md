# HUB 工厂基础生产

HUB 工厂与现有 `factoryControl` 执行器共用一套 carrier 装卸任务。规划器在原工厂阶段内发布目标，主循环顺序不变。启用 HUB 且启用工厂控制后，拥有 storage、terminal 和 factory 的 HUB 自动接入；其它房间继续按原配置执行。

本轮仅纳入 `COMMODITIES` 中无需工厂等级的配方：矿物压缩与解压、电池压缩与解压、wire、cell、alloy、condensate。工厂等级与 Power Creep 技能不会自动变更。

## 库存策略

| 配置 `Memory.cfg.factoryControl.hub` | 默认值 | 行为 |
| --- | --- | --- |
| `enabled` | `true` | 自动规划开关；全局工厂开关与 HUB 开关仍须开启 |
| `planInterval` | 50 tick | 每次复核库存、队列与内部调拨 |
| `productTarget` | 5000 | 压缩矿、电池与基础商品的本房库存目标 |
| `mineralFloor` | 20000 | H/O/U/K/L/Z/X/G 的本地底仓；低于底仓且有压缩矿供应时解压 |
| `energyFloor` | 200000 | 工厂耗能底仓；低于此值且有电池时解压 |
| `energyTarget` | 250000 | 开始解压后持续恢复到此目标，避免立即反向压缩 |
| `energyCompressionStart` | 400000 | 达到此值才开始压缩电池；开始后仍保护耗能底仓 |

目标按完整批次完成，最多超过目标一个配方批次减一。库存计 storage、terminal、factory。耗料还扣除其它生产者的有效预留和已有出库任务；供房同时保护自己的资源控制底仓与工厂底仓。压缩矿只使用 HUB 本地余矿，不为压缩从外房调入原矿。

缺能恢复优先，其次是缺矿恢复，再是有原料的基础商品与余矿压缩。缺少整个内部网络都没有的原料时跳过该配方。矿物与电池的压缩、解压不会同时排入相反方向。每批产出后卸料；达标的最后一批同样卸出。更换配方会清理无关残料。

## 调拨与人工控制

缺料通过既有内部 `ResourceTransferTask` 调度，原因前缀为 `hub:factory:`。每次仅补当前一批缺料；不足 100 的小原料尽量合并为 100，供房剩余不足时允许小批量。健康在途覆盖需求，不重复派单。规划器只取消自己生成且未被 Treasury 接管的自动任务，保留手工调拨。自动 HUB 队列不触发原料市场采购。

房间的显式手写配置、显式停用以及全局手写目标队列优先。自动房间配置带 `managedBy: "hubFactoryPlanner"`。迁移 HUB 或关闭自动规划时，原自动房间撤销生产目标并进入 `drainOnly`，把残留存货卸出；全局关闭工厂控制时装卸任务也暂停。E1N57 的原手动停用配置保留。

## 状态

`Memory.runtime.factoryControl.hubPlan` 保存当前目标、缺料、更新时间和最多 16 条调拨动作。具体执行状态仍在 `rooms[房间名]`，包括当前产品、阶段、缺料、最近成功生产的 tick 与资源、累计产量。HUB 面板的 Factory 栏显示这些状态，CPU 监视和市场生产保护继续复用现有接口。
