# 依据 CPU 优化建议实施的改动与验证

日期：2026-10-16（Asia/Shanghai）。依据用户提供的《screeps-bot-CPU优化建议.md》，以最新 `main @ a9c1f81a` 为基线，在 `codex/cpu-optimization-20261016` 实施。

## 已实施

### 市场摘要的内容缓存

市场预检每 tick 的执行频率保持原样。新增两层只保存计算结果的有界堆缓存：

- 先完整规范化当前对象，只有完整规范字符串相等才复用 v1 摘要。支持 Memory 重解析后的等值新对象；原地修改、undefined、非有限数、循环和非普通对象仍走当前检查。缓存最多 8 条，单条 1,048,576 个 UTF-16 code unit，总长 2,097,152。
- 原始字符串按完整内容复用 JSON 转义，字段名也走同一缓存。FIFO 最多 2,048 条，原始与转义后字符串总长不超过 262,144 个 code unit；长于 4,096 的字符串直接编码。

已有的深冻结对象缓存和长前缀缓存保留。没有缓存授权判断，没有改变摘要 revision、历史字节格式、permit、WAL 或资金责任。

### 诊断与绘图的 bucket 门控

- Hub 绘图默认关闭；显式开启后，默认 bucket 至少 8,000 才绘图，支持到期自动停止。
- 外部遥测默认 bucket 至少 8,000 才导出；允许显式设置 `minBucket: 0` 做低 bucket 定向诊断。跳过时不构建快照、不序列化、不申请 segment，上一份数据的 tick 保持原样。
- 库存影子自动对账在 bucket 低于 8,000 时暂停，不推进轮转或采样时钟；显式 force 仍立即执行。
- Treasury 的只读 shadow observer 最低 bucket 从 2,000 提高到 8,000。生产 begin/end、未决责任恢复和交易门禁不受此门控影响。

临时开启 100 tick 的 Hub 面板：

```js
Memory.cfg.hub.visuals = { enabled: true, untilTick: Game.time + 100 };
```

需要低 bucket 定向观察时显式设置：

```js
Memory.cfg.hub.visuals = { enabled: true, untilTick: Game.time + 100, minBucket: 0 };
Memory.cfg.telemetry.minBucket = 0;
```

### segment 激活协调

新增 `requestMemorySegments()`，同 tick 请求取并集并去重。非法 ID 和超过 10 个的申请整批拒绝；原生调用失败后不提交内部状态，可以重试。Game、RawMemory 或 tick 变化时重新收集申请。遥测已接入，生产源码的 `setActiveSegments` 只留在协调器中。

这是后续迁移冷数据的基础设施，本轮没有迁移或删除许可链。其它使用方需要在每个需要激活的 tick 重新申请；协调器不承担跨 tick 租约、优先级抢占或冷数据恢复。

### 复用当前 tick 查询

- 回收 creep 从 `TickContext.getSpawnsByRoom()` 取得当前房间 spawn，再保留原来的 `isActive()` 筛选。
- 核弹补给查询使用已有的己方结构分组和 creep 快照，避免重复全局展开与结构筛选；预留续租、任务发布与跨房清理频率保持原样。

### 锁文件下载源

按用户追加要求，将锁文件中唯一的腾讯云镜像记录 `fflate@0.8.3` 改为 `https://registry.npmjs.org/fflate/-/fflate-0.8.3.tgz`。版本与 integrity 保持原值。服务器从官方 registry 读取元数据并实际下载 173,034 字节包，三方 SHA-512（官方元数据、实际字节、原锁文件）一致。该依赖供已有的错误堆栈源码映射解压使用，非本轮新增。

## 对原建议的取舍

| 建议 | 本轮处理与理由 |
| --- | --- |
| 全局复用已解析 Memory | 暂不接管：普通堆复用无法仅凭连续 tick 证明外部 Memory 写入未发生，也需要处理未成功持久化的 tick。市场与 Treasury 对真实持久状态的恢复不能以对象连续性替代。 |
| permitChain 迁移 segments | 完成激活协调前置；迁移仍需要 manifest、校验、异步未就绪时的写门禁、完整历史恢复与单独回放。 |
| marketSalePreflight 每 20–50 tick 执行 | 改为降低相同内容的计算成本，保留每 tick 的原检查与恢复。交易数组头 ID 不能覆盖所有配置、订单、许可和资金责任变化。 |
| 核弹控制每 100 tick 执行 | 不采用：现有补给预留 TTL 只有 3 tick，需要续租；本轮改为复用查询。 |
| Hub 工厂规划统一改为低频 | 当前已有 `planInterval` 门控，未再次加入一套调度时钟。 |
| Observer、PowerBank 路线与寻路复用 | 最新 main 已包含近期的走廊复用、不支持路线负缓存及 incomplete 退避，本轮不重复修改。 |
| 更换全部寻路入口、延长全部路径寿命 | 留待独立的路径语义与负载对照；现有 Room.findPath 默认已使用 PathFinder，不能仅换 API 名称就计算收益。 |
| 按固定比例降频战斗、孵化与所有经济模块 | 未统一套用；各模块有时序、续租和当前事实依赖。主循环源码与阶段顺序保持不变。 |

Memory、segment 及寻路语义依据：[官方全局对象说明](https://docs.screeps.com/global-objects.html)、[RawMemory API](https://docs.screeps.com/api/#RawMemory)、[PathFinder.use API](https://docs.screeps.com/api/#PathFinder.use)。

## 验证

所有构建、类型检查、Jest 和性能对照均在专用验证服务器的任务隔离目录执行。本机仅编辑、轻量核查和传输，没有复制部署凭据。原始日志和隔离路径保存在本地忽略目录的证据中。

最终源码的生产 strict 与测试两份类型检查通过。性能对照使用服务器原有的 2026-10-10 历史市场 Memory 快照，以当前 `a9c1f81a` 摘要实现为基线，交替执行先后顺序；fixture 反序列化和输出摘要均不计入计时。

| 对照范围 | 输入与重复次数 | 基线中位耗时 | 候选中位耗时 | 逐组降幅中位数 |
| --- | --- | ---: | ---: | ---: |
| 完整市场预检 | 7 组，每组每版 24 帧 | 3,743.62 ms | 3,388.32 ms | 9.64% |
| 单独许可链摘要 | 761,912 字节历史链；7 组，每组每版 6 帧 | 4,844.43 ms | 89.29 ms | 98.16% |

两项均为 7/7 组输出 SHA256 一致。完整预检每帧还明确断言无拒绝原因、无 blocker、无市场写入；所有市场原生写入入口均禁止。完整预检各组降幅为 5.92%–12.16%。各列分别取中位数，降幅以逐组比值为准。两个范围存在包含关系，收益不能相加。

最终候选另通过 1,200 组摘要差异输入及重解析、原地修改、Unicode、转义字符、整数键、容量边界与超大输入检查。早期仅新增完整摘要缓存时，完整预检降幅约 1.98%；测量后增加了不可变字符串转义缓存，最终结果使用同一份冻结源码重新验证，没有混用早期数字。

| 最终检查 | 结果 |
| --- | --- |
| 生产 strict / 测试类型检查 | 两份配置均通过 |
| 无过滤全量回归 | 264 套件、1,991 用例全部通过；零失败、pending、todo |
| 测试完整性 | `JEST_TEST_INTEGRITY=PASSED`；磁盘、Git 和 Jest 清单一致，运行前后输入身份一致 |

首轮完整运行失败来自传输带入的 macOS AppleDouble 元数据：额外 264 个 `._*.test.ts` 被识别成伪测试，文件清单检查也因此失败。按 AppleDouble 魔数清理了任务目录中 647 个传输副产物，保持测试配置与断言不变；逐项比对 623 个真实输入后，重新执行完整检查。最终全量与构建已经包含官方 registry 的锁文件修正，未使用失败那一轮代替验收。

机器可读汇总和原始结果位于本工作树的 `monitor-data/cpu-optimization-20261016/evidence/`，其中 `full-clean/` 是最终完整回归，`full/` 是服务器保留的首次失败记录。性能对照的临时测试已在全量运行前移出源码目录，不计入 264 套件或 1,991 用例。

本轮没有上传游戏代码、修改线上配置或递增版本。服务器的 Git commit 仅为隔离验证快照，不是可发布身份。线上 CPU 收益需要发布后取得同版本 warm 窗口；服务器耗时不能换算为 shard1 CPU。
